# 0003: Pilot sign-in with invitation codes, no authentication library

Date: 2026-11-14 (owner decision)

## Context

Backlog C3 asks for sign-in for five pilot students in one organization. `ARCHITECTURE.md` requires that no external authentication service is mandatory and that users are stored in our database.

## Options

1. An authentication library (sessions, providers, email flows).
2. Invitation codes handled by our own code, reusing the signed cookie of decision 0002.

## Decision

Option 2 for the pilot:

- **One long random code per student**, generated by the server (at least 128 bits of randomness), given to the student once.
- **Stored hashed** in our database (SHA-256 of the code; the code is random enough that a slow password hash adds nothing). The plain code is never stored or logged.
- **A limit on failed attempts** per client within a time window; beyond it, sign-in is refused for a while.
- **The existing signed, http-only cookie** carries the identity after sign-in. No new dependency.

## Consequences

- No password, no email: a lost code is replaced by the owner, which invalidates the old one.
- An authentication library will be chosen, and recorded in a new decision, when email sign-in and parent accounts arrive.
